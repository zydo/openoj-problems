# Cut And Paste Rebuild

## Description

You are handed two integer arrays, `nums1` and `nums2`, of equal length
`n`, and you want to rebuild `nums1` into `nums2`.

A single move takes one contiguous block of `nums1` out of the array and
drops it back in somewhere else, without reordering the block itself:
select `nums1[L..R]`, pull it out so that the elements before and after it
close up, then insert the whole block at any position in what is left —
before the first element, after the last one, or between any two neighbors.

Return the fewest moves that turn `nums1` into `nums2`.

### Example 1

```text
Input: nums1 = [2,4,6,8], nums2 = [4,6,2,8]
Output: 1
Explanation:
Lift the block [4,6] out; the leftover array is [2,8].
Drop the block in front of them: [4,6,2,8].
```

### Example 2

```text
Input: nums1 = [5,1,3,2], nums2 = [1,2,3,5]
Output: 2
Explanation:
Move the leading 5's neighbor: take the block [1] (L = 1, R = 1) and
paste it at the very front, giving [1,5,3,2].
Then take the block [2] (L = 3, R = 3) and paste it between 1 and 5,
giving [1,2,3,5].
```

### Example 3

```text
Input: nums1 = [7,3], nums2 = [3,7]
Output: 1
Explanation:
Cut out the 7 and paste it after the 3.
```

### Example 4

```text
Input: nums1 = [9,9,4], nums2 = [9,9,4]
Output: 0
Explanation:
The arrays already match, so no move is needed.
```

### Constraints

- `2 <= n == nums1.length == nums2.length <= 6`
- `-10^5 <= nums1[i], nums2[i] <= 10^5`
- `nums2` contains exactly the elements of `nums1`, just possibly in a
  different order.

## Hints

### Hint 1

Treat each intermediate arrangement of the array as a node in a graph and
explore outward from `nums1` level by level until `nums2` shows up.

### Hint 2

Every move costs the same, so the first time you reach `nums2` you have
found a cheapest sequence.

### Hint 3

A move is generated by picking a start index, an end index for the block,
and an insertion slot in the remainder — enumerate all three.

### Hint 4

Remember which arrangements you have already produced so identical states
are never expanded twice; with `n <= 6` there are at most `6!` of them.
