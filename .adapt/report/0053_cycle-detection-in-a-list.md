### Notes

- **Family: `cycle`, written back to back with `0054_cycle-entry-in-a-list`.**
  Shared framing vocabulary, deliberately identical in both statements: the
  structure is a **chain** of **nodes**; a node's pointer is its **outgoing
  link**; a cycle exists when following links "returns you to a node you have
  already stood on"; the two-speed method is described as two **walkers**. The
  wire-form paragraph ("The judge cannot hand you node objects, so the chain
  arrives flattened into two arguments…") is the same in both, with only the
  final sentence differing — detect versus locate. Constraints use the same
  three-bullet prose form in both.
- **`pos` was renamed to `tailLink` in both siblings.** It is LeetCode's own
  term — the source statement introduces it with "Internally, `pos` is used to
  denote…" — so keeping it would leave the most LeetCode-flavoured identifier
  in the bundle untouched. `tailLink` says what the number is. Renaming a
  parameter is free for the compatibility gate (arguments bind positionally),
  but the reference solutions must be renamed to match the regenerated
  starters. Rust solutions take `tail_link`, matching the bank's existing
  practice of camelCase parameters in `problem.json` (hence in the starters)
  with snake_case in the rust reference — see `0127_word-ladder` for the same
  split.
- **The back edge in a cycle figure is geometry, not a label.** The curve's
  control points name the node it lands on, so `tailLink` cannot be changed by
  a text edit alone. Here the change was two numbers in one path, generated by
  the same construction the original used (drop to `y = 110`, run across, come
  back up), so it stays a safe edit — but a bundle that needs a *different
  number of nodes* would need a redraw, not an edit.
- Blind renaming produced the comment "Point the tail back at index tailLink to
  close the cycle", which reads badly; it was rewritten to "Close the cycle by
  pointing the tail at the given index" in all fourteen solution files.
